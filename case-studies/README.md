# Case studies

This folder contains concise, public-safe descriptions of work that informs my QA and technical-support practice.

## Reading the labels

- `[SANITIZED WORK CASE]` — based on real work. Names, identifiers, dates, screenshots, video, internal URLs, tickets, and user data are withheld or generalized.
- `[LEARNING PROJECT]` — a local educational project or a practice artefact. It is not represented as an employer deliverable or a production release.

## Evidence standard

Each work case explains the context, my role, how I worked, and the boundary of what can be shared. It deliberately avoids invented metrics, release claims, or screenshots from closed systems.

When a public-safe evidence item is available, it should include:

1. A clear source and date.
2. A disposable or redacted environment.
3. No credentials, internal links, participant data, or customer data.
4. A note saying whether it is a planned test, an executed test run, a code review observation, or an anonymized work example.

See the [repository evidence policy](../evidence/README.md) for the full publishing checklist.
